SatLink Share PRO PC 4.1 / Android 3.1
TCP port: 8988
UDP discovery port: 8989
Protocol header: SATLINK_SHARE_PRO_V3_RESUME
Folder header: SATLINK_SHARE_PRO_V4_FOLDERS
For V4 each file name is a UTF relative path rooted at the selected folder, e.g. Pictures/Trip/photo.jpg.
Metadata and streaming/resume framing are unchanged from V3. Both updated receivers accept V3 and V4.
Folder transfer requires updated sender and receiver. Empty directories are not transmitted.
Discovery request: SATLINK_SHARE_PRO_DISCOVER_V1
Discovery response: SATLINK_SHARE_PRO_RESPONSE_V1|<name>|8988

PC v3.1 can:
- respond to Android discovery so PC appears in Android devices list
- scan for Android receivers
- receive files from Android using Java DataOutputStream/DataInputStream protocol
- send files to Android using the same protocol

V5 (Android 3.1 / PC 4.1): header SATLINK_SHARE_PRO_V5_ACK. Same as V4 (relative paths), plus:
after the last byte of each file the receiver saves it, then writes an 8-byte long = file size.
The sender marks the file complete and starts the next one only after this confirmation.
If the receiver already saved the same file (same sender, name, size) in the last 15 minutes and
the confirmation was lost, it answers resume = size followed by the confirmation, so no duplicate is made.
Senders try V5 first and fall back to V3/V4 if an older receiver closes the connection.
Senders reconnect up to 10 times and resume from the last byte.
